Mindflower STEP Mail

Privacy Policy

Last updated: 15 October 2026

Mindflower is operated by the owner of the dedicated Gmail account used for STEP messages. The integration requests read-only access so the owner can monitor official U.S. Department of State STEP mail.

Data accessed and use

The integration reads message IDs, Gmail receipt timestamps, and raw message content. It stores raw mail encrypted in the owner's protected local database. It uses this data to identify service mail, verify message signatures, and examine possible official updates. It does not send, modify, label, delete, or unsubscribe from messages.

Messages may contain personal information, links, or one-time codes. The pilot keeps message content out of application logs and reports. Potential alert text is sanitized before any future model-assisted analysis; that step is currently disabled for Gmail mail and requires separate owner approval.

Sharing, storage, and deletion

The pilot does not share Gmail content with Telegram subscribers, AI providers, or third parties. Encrypted raw mail is held in a local database accessible to the owner. There is currently no automatic deletion period for that pilot database; the owner controls its retention and can delete the database and backups. Future production retention rules must be set before deployment.

If the owner explicitly selects a verified message for review, the app can store a local text copy with email addresses, web links, and short numeric codes removed. This copy is held in the protected local database and a restricted local file. It is not fully anonymous and may contain names or context. Staging does not send it to an AI provider or Telegram user and does not publish an alert.

The owner can revoke Gmail access in Google Account settings. Revocation stops future reads but does not automatically delete already captured encrypted mail. The owner can delete that local data separately.

Scope and security

The only requested Google scope is https://www.googleapis.com/auth/gmail.readonly. OAuth credentials and the raw-mail encryption key are stored outside the source repository with restricted file permissions. Access is limited to one dedicated mailbox.

Questions can be sent to the developer contact shown on the Google OAuth consent screen.
